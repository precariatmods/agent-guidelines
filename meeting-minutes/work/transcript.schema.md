# transcript.csv schema

音声から作成する文字起こしデータです。1行を1つの発話単位とし、音声の先頭からの時刻、話者ID、発話内容を記録します。音声認識直後は`transcript_raw.csv`、話者分離・人物確認後は`transcript.csv`として同じ列構造を使用します。

## ファイル仕様

| 項目 | 定義 |
|---|---|
| 保存先 | `work/transcript_raw.csv`、`work/transcript.csv` |
| 文字コード | UTF-8（BOM付き） |
| 区切り文字 | カンマ |
| 改行 | CRLF |
| ヘッダー | 必須 |
| 並び順 | `start_time`の昇順。同時刻の場合は音声で確認できる順 |

カンマ、ダブルクォートを含む値はダブルクォートで囲み、値の中のダブルクォートは2つ重ねます。発話内の改行は半角スペースへ置換し、1レコードを1行で保存します。

## 列定義

列の順番は次のとおり固定します。

| 列名 | 必須 | 型・形式 | 定義 |
|---|---:|---|---|
| `line_id` | 必須 | 文字列 `line_000001` | 発話単位の一意なID。音声順に連番を付け、後工程でも変更しない |
| `speaker_id` | 必須 | 文字列 | 未確認の話者は`speaker_001`、確認済みの人物は`person:<ID>`を使用する |
| `start_time` | 必須 | `HH:MM:SS.mmm` | 音声先頭を `00:00:00.000` とした発話開始時刻 |
| `end_time` | 必須 | `HH:MM:SS.mmm` | 発話終了時刻。`start_time`より後の時刻とする |
| `text` | 必須 | 文字列 | 元の発話に近い文字起こし。要約や決定事項の抽出は行わない |

ヘッダー行：

```csv
line_id,speaker_id,start_time,end_time,text
```

## 記録ルール

- 話者名が不明な場合は、登場順に `speaker_001`、`speaker_002` のように仮IDを付ける。
- 同じ人物には、ファイル全体を通じて同じ `speaker_id` を使用する。
- 音声から氏名を取得できた場合は`work/master/person.csv`と照合し、候補の氏名・部署をチャットで利用者へ提示する。
- 利用者が人物を確認した後、その話者の`speaker_id`を`person:<ID>`へ置き換える。例えば人物マスターの`ID`が`4`なら`person:4`とする。
- 声の特徴クラスタと仮話者ID・人物IDの対応は`speaker_candidates.csv`へ保存する。
- 一つの文字起こし区間に複数話者が含まれる場合は、時刻の重なりが最大の話者を暫定割り当てし、音声で確認する。
- 人物を確認できない場合は、仮IDのまま保持する。
- 発話が重なった場合は話者ごとに行を分け、対応する時刻をそれぞれ記録する。
- `えー`、`あのー`、言い直しなども、第一段階では原則として残す。
- 聞き取れない箇所は推測せず、`[聞き取り不明 00:01:23.450]` の形式で記録する。
- 人名、会社名、製品名など表記に確信がない場合は、推測で確定せず `〔要確認：聞こえた表記〕` と記録する。
- 意味のある非言語音は `[笑い]`、`[拍手]`、`[長い無音]` のように角括弧で記録する。
- 無音だけの区間は通常は行として作成しない。
- `text`に議事録向けの要約、担当者、期限、判断結果を追加しない。これらは第二段階の`summary.csv`で扱う。

## 記入例

```csv
line_id,speaker_id,start_time,end_time,text
line_000001,speaker_001,00:00:01.240,00:00:05.810,それでは定例会議を始めます。
line_000002,speaker_002,00:00:06.120,00:00:12.540,"先月の売上は、目標を少し上回りました。"
line_000003,speaker_001,00:00:13.030,00:00:16.220,[聞き取り不明 00:00:14.860]について確認します。
```

## 完成条件

- すべてのデータ行に5列が存在する。
- `line_id`が重複していない。
- `speaker_id`が発話者ごとに一貫している。
- `start_time`と`end_time`が音声の該当箇所に対応している。
- 各行で`end_time`が`start_time`より後になっている。
- 不明な内容や固有名詞が推測で補完されていない。
- 音声全体の対象範囲に、大きな文字起こし漏れがない。
