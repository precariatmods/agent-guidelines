# Meeting Minutes — AIによる会議議事録作成サンプル

会議音声から文字起こしと話者分離を行い、利用者との対話によって会議情報と発言者を確認し、Excelで表示する議事録を作成するサンプルです。

AIがすべてを自動確定するのではなく、**AIが候補を作り、人間が確認して完成させる**ことを目的としています。

処理の方針は `POLICY.md` を正本とします。

## ⚠️ 初回実行時の重要事項

このサンプルでは、音声認識と話者分離のために、大規模なPythonライブラリとAIモデルを使用します。

**初回実行時には、環境によって最大約2GBの保存容量を使用する可能性があります。**

- 多数の依存ライブラリがインストールされます。
- Whisperと公開ONNX話者特徴モデルをダウンロードします。
- インターネット接続が必要です。
- インストールには時間がかかる場合があります。
- 必要な環境がすでに存在する場合、再インストールは行いません。

`setup.ps1` はインストール前に既存環境を確認します。不足がある場合は容量について警告し、利用者が `y` または `yes` を入力した場合だけインストールします。

許可なく大量のライブラリをインストールすることを避ける設計です。

※ 約2GBは環境構築時の目安であり、ディスク使用量の厳密な上限ではありません。

## 1. 必要な環境

- Windows
- PowerShell
- Python 3.11 推奨
- インターネット接続
- Microsoft Excel（最終帳票の表示用）

CPUで動作する構成を基本としています。GPUは必須ではありません。

## 2. 必要なpipパッケージ

直接指定するパッケージは次の2種類です。

| パッケージ | バージョン | 役割 |
|---|---|---|
| faster-whisper | 1.2.1 | 会議音声の全文文字起こし |
| sherpa-onnx | 1.13.8 | 声の特徴抽出 |

`scripts/requirements.txt` に定義されています。

```text
faster-whisper==1.2.1
sherpa-onnx==1.13.8
```

実際のインストールでは、これらが必要とする依存パッケージもpipによって導入されます。

主な関連ライブラリには、次のものがあります。

| ライブラリ | 主な役割 |
|---|---|
| 3D-Speaker ONNXモデル | 発言区間の声の特徴抽出 |
| ctranslate2 | Whisperの高速推論 |
| huggingface-hub | AIモデルの取得・管理 |
| tokenizers | テキストのトークン処理 |
| numpy | 数値計算 |

これらは関連する依存パッケージの例です。直接インストールするパッケージ一覧の正本は `scripts/requirements.txt` とし、環境に応じた依存関係の解決はpipに任せます。

Excelファイルはコピーするだけなので、`openpyxl` などのExcel編集用ライブラリは必要ありません。

## 4. 初回の環境構築

PowerShellで `meeting-minutes` フォルダへ移動します。

次のコマンドを実行します。

```powershell
.\setup.ps1
```

最初に導入済みのPythonとライブラリを確認します。

必要な環境が不足している場合だけ、インストールの確認が表示されます。

```text
初回の環境構築が必要です。

Pythonライブラリと音声モデルの保存に、
最大約2GBの空き容量を使用する可能性があります。

meeting-minutes内へインストールしますか？ [y/N]
```

`y` または `yes` でインストールを許可します。

それ以外の入力ではインストールを中止します。

構築する環境は原則として次の場所に保存します。

| フォルダ・ファイル | 内容 |
|---|---|
| `.venv/` | Python仮想環境 |
| `.cache/` | AIモデル、pipなどのキャッシュ |
| `.python-path` | 使用するPython実行環境の記録 |

既存の適合するPython環境がある場合には、その環境を再利用する場合があります。

`run.ps1`が`setup.ps1`を呼ぶのは、`.python-path`がない初回だけです。通常実行では軽量なパッケージ版数確認だけを行います。環境のハッシュや確認済み記録は管理しません。

なお、確認を省略する `.\setup.ps1 -Yes` は自動実行などで明示的に許可する場合のみ使用してください。

## 5. 会議音声の処理

会議音声を `input/` に保存します。

実行例：

```powershell
.\run.ps1 -Audio "input\meeting_voice.mp3"
```

主な処理は次のとおりです。

1. Whisperで音声全体を文字起こしする。
2. `work/transcript_raw.csv` に保存する。
3. sherpa-onnxで各発言区間の声の特徴を抽出し、仮話者IDへ分類する。
4. 話者IDごとの発言例を抽出する。
5. 人物マスターの候補を提示する。
6. 利用者が確認した話者を人物IDに紐付ける。
7. 中間CSVを `work/` に保存する。

人物を確定せず、話者候補まで生成する非対話モードも利用できます。

```powershell
.\run.ps1 -Audio "input\meeting_voice.mp3" -NonInteractive
```

既存の`work/transcript_raw.csv`は自動再利用しません。同じ音声から作成したものと確認済みの場合だけ、次のように明示します。

```powershell
.\run.ps1 -Audio "input\meeting_voice.mp3" -ReuseTranscript
```

確認できない場合は`-Force`で文字起こしから作り直します。

## 6. AIと利用者による内容確認

文字起こし結果をもとに、会議情報と発言者を確認します。

### 会議情報の確認

対象となる項目は次の5つです。

- 会議名
- 開催日
- 開始時刻
- 終了時刻
- 場所

不明な項目は推測で確定せず、利用者に確認します。

### 発言者の確認

話者分離で検出した話者IDについて、主要発言を提示します。

人物候補は `work/master/person.csv` を参照します。

声や発言内容だけで人物を確定せず、利用者の確認を得て紐付けます。

判断できない人物は未確認として扱います。

確認方法の詳細は `POLICY.md` を参照してください。

### 議事録の作成

確認済みの文字起こしから次の情報を整理します。

- 時系列の発言内容
- 議題
- 議論内容
- 決定事項
- 参加者情報

この工程はAIによる内容整理と利用者の確認を前提としています。

**現在の `run.ps1` は、文字起こしと話者紐付けまでを実行します。議事録要約と最終4種類のCSV作成は別工程です。**

## 7. 最終成果物

最終的に `output/` へ次の5ファイルを保存します。

```text
output/
├─ header.csv
├─ minutes.csv
├─ participants.csv
├─ Agenda.csv
└─ meeting.xlsx
```

各ファイルの用途は以下のとおりです。

| ファイル | 内容 |
|---|---|
| header.csv | 会議名、日時、場所 |
| minutes.csv | 時系列の議事内容 |
| participants.csv | 参加者情報 |
| Agenda.csv | 議題、内容、決定事項 |
| meeting.xlsx | Excelで表示する議事録帳票 |

4種類のCSVはUTF-8（BOM付き）、CRLFで保存します。

列名と列順は `template/` の対応するCSVに合わせます。

## 8. Excel帳票の作成方法

このサンプルではPythonからExcelを編集しません。

処理の役割を次のように分離しています。

**AI・Pythonの役割**

- 音声認識
- 話者分離
- 内容整理
- CSVファイルの生成

**Excelの役割**

- CSVデータの取り込み
- 議事録の表示
- 既存レイアウトの維持
- 印刷

4種類のCSVが完成したら、次のスクリプトを実行します。

```powershell
python scripts\finalize_meeting.py output
```

このスクリプトはCSVの列名とデータ行の有無を検証し、`template/meeting.xlsx` を `output/meeting.xlsx` にそのままコピーします。

既存の `meeting.xlsx` を上書きする場合は `--force` を指定します。

### Excelへのデータ反映

`output/meeting.xlsx` をExcelで開きます。

Excelの **［データ］→［すべて更新］** を実行し、CSVを読み込みます。

Excel原本にはCSVへのデータ接続を設定する設計ですが、実行環境によって接続先が異なる場合があります。

その場合は、利用者自身が `output/` 内のCSVファイルをデータ接続先に指定してください。

CSVとの接続が正常に機能すれば、既存のExcelレイアウトに議事録データが反映されます。

※ Excelの接続設定や外部データ更新に関する確認が表示される場合は、内容を確認して操作してください。

## 9. このサンプルの特徴

このサンプルでは次の考え方を採用しています。

- 方針をMarkdownファイルに記述し、AIの処理判断を制御する。
- 音声認識と話者分離をPythonで行う。
- 人物や会議情報をAIの推測だけで確定しない。
- 確認済みの情報をCSVとして保存する。
- ExcelのレイアウトをPythonで変更しない。
- Excelへのデータ反映は既存のデータ接続を利用する。

**AIはデータを作り、Excelはデータを表示する。**

この役割分担によって、Excel帳票のデザインとAIによるデータ生成を独立して管理できます。

## 10. 注意事項

- 初回は多数の依存ライブラリとAIモデルをダウンロードする可能性があります。
- 話者分類は声の特徴による推定であり、重なり発話や短い発言では誤分類する場合があります。
- 既存のPython環境やパッケージの組み合わせによって、環境構築に失敗する場合があります。
- 音声認識、話者分離、要約の結果は正確性を保証しません。
- 人名、会議日時、決定事項は必ず利用者が確認してください。
- ExcelへのCSVデータ接続は利用者の実行環境によって再設定が必要な場合があります。
- 音声データ、人物マスター、議事録には機密情報や個人情報が含まれる可能性があります。GitHubへ公開する前に確認してください。

このサンプルは、AIにすべてを任せるためではなく、**AIの処理と人間の確認、既存のExcel帳票を組み合わせる方法を学ぶためのもの**です。
