# ダウンロードしたSkillの安全確認ガイド

この文書は、ダウンロードまたは更新した`literary-kamishibai`の内容を、利用者が実行前に確認したいときに使う任意のガイドである。通常の制作で毎回読む必要はなく、この確認を行わないとスキルを使えないという意味でもない。

動画や講座で「ダウンロードしたスキルを最初に確認する方法」を説明するときにも利用できる。

目的は「安全だと信じてもらう」ことではなく、利用者自身が処理内容、必要な権限、影響範囲を確認できるようにすることである。この文書だけで絶対的な安全性を保証するものではない。

## まず確認したい場合

ダウンロードしたスキルのフォルダをCodexで開き、まだスクリプトを実行せず、次のように依頼する。

```text
このフォルダ内のスキルを実行せず、読み取りだけで確認してください。
次の点を日本語で報告してください。

・同梱されているファイルの種類
・実行ファイルやインストーラーの有無
・ネットワーク通信やダウンロード処理の有無
・外部プログラムを起動する処理の有無
・ファイルの削除、上書き、移動を行う処理の有無
・書き込み先が指定した作業フォルダ内に限定されているか
・固定されたPC固有パス、秘密情報、個人情報の有無

問題が疑われる場合は実行せず、対象ファイルと理由を示してください。
```

結果を確認し、内容や追加権限の理由が分からない場合は実行しない。問題がなければ、通常のREADMEと使用例へ進む。

## 1. このスキルで確認できる基本原則

- AIへの指示、スクリプト、テンプレート、参照文書を公開する。
- EXE、MSI、DLLなど、内容を通常のテキストとして監査できない実行バイナリを同梱しない。
- 外部バイナリ、インストーラー、非公開ツールを自動でダウンロードまたは実行しない。
- 作者個人のPC、固定ドライブ、非公開補助ツールを前提にしない。
- 利用者が指定した作業フォルダを処理の基準にする。
- 必要な権限と変更範囲をREADMEへ明記する。
- 公開ソースであることを安全性の保証とは表現しない。

## 2. 配布物に含めないもの

- `.exe`、`.msi`、`.dll`、`.com`、`.scr`などの実行バイナリ
- 作者個人が作成した非公開アプリ
- 出所や権利関係を説明できない素材
- APIキー、パスワード、Cookie、トークン、個人情報
- PC固有の絶対パスやユーザー名を含む設定
- 外部ソフトを無人でインストールするPowerShell、バッチ、シェル処理
- 難読化、暗号化、動的取得によって処理内容を隠すコード

Pythonなどのソースコードも無条件に安全とは扱わない。採用理由は、利用者が処理内容を監査しやすいためである。

## 3. ファイル操作の制限

公開版は、次の条件を満たすこと。

- 新規プロジェクトは、利用者が指定した作業フォルダの配下に作成する。
- 既存の同名ファイルや同名プロジェクトを上書きしない。
- スキルが削除できるのは、今回の実行でスキル自身が新規作成したものに限る。
- 削除が必要な場合は、対象の絶対パスと理由を事前に表示し、利用者の明示的な確認を得る。
- `C:\Temp`のような固定の絶対パスを、一時領域や削除対象として決め打ちしない。
- 作業フォルダ全体、ドライブ直下、ホームディレクトリなどを再帰削除の対象にしない。
- ワイルドカードだけで削除対象を決めない。
- パスを正規化し、`..`、シンボリックリンク、ジャンクションなどによる作業範囲外への逸脱を確認する。
- 完成後の整理は、削除よりも復元可能な退避を優先する。

親フォルダを削除する場合は、スキルが作成したフォルダであり、空であることを確認する。複数作品を格納する`scenario/projects`全体を無条件に削除してはならない。

## 4. ネットワークと外部ツール

- プロジェクト作成のためにネットワーク接続を要求しない。
- ダウンロード、Web送信、API呼び出しが必要な工程は、目的、送信対象、接続先を実行前に説明する。
- ネットワーク権限を包括的または恒久的に要求しない。
- VOICEVOX、Node.js、Remotion、ffmpegなどは同梱せず、利用者が公式配布元から導入する。
- 外部ツールの導入や更新をスキルが自動実行しない。
- 導入済みの外部ツールを使う場合も、利用者が依頼した制作段階だけで起動する。
- 作者個人の補助ツールや非公式ミラーを推奨しない。

## 5. 現在の同梱スクリプトの影響範囲

`scripts/create_project.py`は、次の処理だけを行う。

- 同梱した`assets/basetemplate/`を読み取る。
- 利用者が明示した原文ファイルまたは企画メモを、指定された場合だけ読み取る。
- `<workspace>/scenario/projects/<project_id>/`を新規作成する。
- 新規作成したプロジェクト内の`job.json`と下書き用文書を更新する。

このスクリプトは、ネットワーク通信、外部プロセス起動、ソフトウェアのインストール、既存プロジェクトの上書き、ファイル削除を行わない。

## 6. ダウンロード後の任意確認手順

安全確認を行いたい場合は、次の順で確認する。動画や講座では、この流れを任意の確認方法として紹介できる。

1. GitHubから専用フォルダへダウンロードして展開する。
2. 展開したフォルダだけをCodexの作業場所として開く。
3. 最初は対象スクリプトを実行せず、読み取りによる静的確認を依頼する。
4. ネットワーク、外部プログラム、削除、上書き、作業フォルダ外へのアクセスの有無を確認する。
5. 問題がなければ、必要な作業フォルダ内だけの書き込みを許可する。
6. 理由が分からない追加権限は許可せず、処理を停止して確認する。

短い確認依頼の例:

```text
このフォルダ内のスキルを実行せずに確認してください。
ネットワーク通信、外部プログラムの起動、削除、上書き、
作業フォルダ外への書き込みがないか報告してください。
```

## 7. 作者・配布者向け公開前チェックリスト

以下はスキルを公開・更新する作者側の確認項目であり、通常利用者の必須作業ではない。

- [ ] 配布対象の全ファイルを一覧で確認した
- [ ] 実行バイナリとインストーラーが含まれていない
- [ ] 秘密情報と個人情報が含まれていない
- [ ] PC固有の絶対パスと非公開ツールへの参照がない
- [ ] ネットワーク通信とダウンロード処理の有無を確認した
- [ ] 外部プロセスを起動する箇所を確認した
- [ ] 削除、移動、上書き、再帰操作を確認した
- [ ] 書き込み先が明示した作業範囲内に収まる
- [ ] 既存プロジェクトに対する上書き拒否を確認した
- [ ] 異常終了時に既存データを壊さないことを確認した
- [ ] テンプレートに不要な制作物や権利不明素材が残っていない
- [ ] READMEの必要ツール、権限、影響範囲が実装と一致している
- [ ] 配布するタグまたはコミットと、検査した版が一致している
- [ ] 新規の空の作業フォルダで動作確認した

## 9. 更新時の扱い

- 初回だけでなく、更新のたびにこのチェックリストを実施する。
- 安全性に関係する変更は、更新履歴で目立つように説明する。
- 配布版にはバージョンまたはGitコミットを付け、利用者が確認した版を識別できるようにする。
- 問題が見つかった版は配布を停止し、影響範囲と対処方法を公開する。

## 10. Python、VOICEVOX、Remotionの安全境界

- 内容を確認できるPythonソースは、目的、読み取り元、書き込み先を確認したうえで使用してよい。
- `sol.exe`は起動、呼び出し、推奨、配布物への同梱をしない。
- `sol.dll`、`sol.deps.json`、`sol.runtimeconfig.json`、`sol.pdb`など、`sol.exe`に付随するバイナリや実行構成物も使用・同梱しない。
- 既存環境にこれらのファイルが存在しても、削除を自動実行しない。公開対象と実行対象から除外する。
- VOICEVOXは公式配布物を利用者自身が導入する。音声生成APIの接続先は原則としてローカルPCの`http://localhost:50021`に限定する。
- VOICEVOX接続先を外部URLへ変更する場合は、送信される文章、接続先、利用規約、認証情報、ログ保存方針を説明し、利用者の承認を得る。
- Remotionとnpm依存関係の導入前に`package.json`、ロックファイル、配布元を確認する。ロックファイルがある場合は再現可能な導入方法を優先する。
- VOICEVOX、Remotion、ffmpegなどの外部プロセスは、利用者が依頼した工程と対象作品に限って実行する。
- MP4は「動画化」または「MP4レンダリング」が明示された場合だけ生成し、対象作品の出力フォルダ内へ保存する。

## 11. ChatGPTから受け取る制作データ

ChatGPTからCodexへ渡す標準の制御ファイルは次の5点とする。

```text
input/dialogue.json
input/scenes.json
input/sfx_cues.json
masters/character_master.csv
masters/voice_style_master.csv
```

シーン画像は可変数の付属素材とし、`images/scene_001.png`のように保存する。受け取ったJSON、CSV、画像、アーカイブは信頼済みとみなさず、外部ツールへ渡す前に静的検査する。

最低限、次を確認する。

- JSONとCSVが指定形式として読み込める。
- `line_id`、`scene_id`、`sfx_id`に重複がない。
- `dialogue.json`の全scene_idが`scenes.json`に存在する。
- `scenes.json`の全line_idsが`dialogue.json`に存在し、各lineが1シーンだけに所属する。
- dialogueの全speakerが`character_master.csv`に存在する。
- 使用する全「VOICEVOX話者＋emotion」が`voice_style_master.csv`に存在する。
- VOICEVOXの話者名、style名、speaker_idが、対象PCで取得した利用可能一覧と一致する。
- `scenes.json`の`image_file`が実画像名と大文字・小文字、番号、拡張子まで完全一致する。
- 効果音ファイル名が実在する提供済み素材と完全一致する。未提供なら`sfx_cues.json`は空配列とする。
- ファイル名とアーカイブ内パスに絶対パス、`..`、ドライブ指定、UNCパス、シンボリックリンクによる作業範囲外参照がない。
- JSONやCSVの文字列をコマンドとして評価しない。外部プロセスへ渡す値は引数として扱い、シェル文字列へ連結しない。
- 画像が想定形式で読み込め、画像を装った実行ファイルや二重拡張子ではない。

検査に失敗した場合はVOICEVOX生成、素材コピー、Remotion配置、レンダリングを開始しない。不足ファイル名、参照元、失敗理由を利用者へ報告し、修正版を受け取った後に最初から検査する。

## 12. ChatGPT受け渡し後の書き込み範囲

- 5ファイルは、利用者が指定した`<workspace>/scenario/projects/<project_id>/`の対応先だけへ配置する。
- 同名の既存ファイルがある場合は、自動上書きしない。差分を提示し、利用者が承認した対象だけを更新する。
- シーン画像を配置する前に、`scene_id`と`image_file`の対応表を作り、既存画像との衝突を確認する。
- 受け取ったZIPなどのアーカイブを展開する場合は、展開後の全パスが新規の一時フォルダ内に収まることを確認してから、必要ファイルだけを作品フォルダへ移す。
- WAV、timeline、Remotion内部JSON、manifest、MP4は入力から生成される成果物として分離し、ChatGPTが生成済みと主張しても検証なしに採用しない。
- 公開前に固定ドライブ、ユーザー名、APIキー、トークン、原文や素材の権利情報、VOICEVOXクレジットを再確認する。

## 13. 追加の公開前チェック

- [ ] `sol.exe`と関連バイナリが配布物に含まれていない
- [ ] Pythonソースの読み取り元、書き込み先、ネットワーク処理を確認した
- [ ] VOICEVOXの接続先が`localhost`、または承認済みの接続先である
- [ ] ChatGPT由来の5ファイルを構文・相互参照まで検証した
- [ ] scene_id、image_file、実画像名が完全一致している
- [ ] アーカイブ展開による作業範囲外への書き込みがない
- [ ] 未確認の効果音名やVOICEVOX speaker_idを採用していない
- [ ] Remotion配置依頼だけでMP4を生成しない
