# Learning Tools 共通方針

## 目的

`learning-tools`は、専門家が選んだ固定教材と指導方針に基づき、AIとの対話や必要に応じた視覚実験を通して理解を深める学習・研修用サンプルです。教材作成者が教材構造・前提・学習段階・教師Policyを設計し、AIが段階ごとの教師ロールを切り替えながら、「知る」から「人に説明できる」まで支援します。

単にPDFを要約したり、一般的な知識を説明したりすることを目的としません。教材作成者が「何を、どの順序で、どのように考えさせ、何をもって理解できたとするか」を定義し、AIはその方針に沿って指導します。

学校・塾の教材だけでなく、企業コンプライアンス、情報セキュリティ、新入社員教育、安全教育、業務手順、宗教教材などにも同じ考え方を適用できます。文章と対話だけで進める非プログラム教材も対象です。

## 共通自動化モデル

教材を含む自動化は、次の4要素で整理します。

```text
Input → Skill + Policy → Output
```

| 要素 | 定義 | Learning Toolsでの例 |
|---|---|---|
| Input | 何を受け取るか | 固定教材、問題、学習目標、画像、初期条件 |
| Skill | どう処理するか | 質問、誤解の推定、段階的なヒント、計算、Figure生成、言い換え |
| Policy | どの順序・条件・制約で処理するか | 最初の問題、回答を待つ規則、実験条件、合格基準、教材範囲 |
| Output | 何をどこへ出すか | 学習レポート、解説、グラフ、理解度の講評、復習計画 |

Skillは「できること」、Policyは「どの教師ロールが、いつ、どの順番で、どこまでSkillを使うか」と区別します。教材の構造化と教師ロールの切り替えは、この4要素を具体化する設計であり、別の自動化モデルにはしません。

Matplotlib、Streamlit、Pythonなどは独立した5つ目の要素にしません。これらはSkillを実現するための実装手段として扱います。

現在の標準ファイルとの主な対応は次のとおりです。

| 要素 | 主に定義する場所 |
|---|---|
| Input | `input.md`、`input/` |
| Skill | `processing.md`、Pythonプログラム、必要な場合の`SKILL.md` |
| Policy | `instructions.md`、`work/guideline.md`、`work/rubric.md`、`work/misconceptions.md` |
| Output | `Output.md`、`output/` |

一つの定義を複数ファイルへ重複させません。具体的な出力先と完成条件は、各教材の`Output.md`を唯一の正本とします。

## Input

各教材の`input.md`は、教材作成者が用意した固定資料と学習課題を定義します。利用者が実行時に新しい入力ファイルを用意することは前提にしません。

代表的なInputは次のとおりです。

- 問題または研修資料のPDF
- 学習対象となる問題一覧
- 教材で使用する画像やデータ
- 学習目標
- 教材作成者が承認した初期条件

学習者の回答は、事前に用意するInputではありません。学習中に発生する対話情報として扱い、必要な部分を学習レポートへ記録します。

固定資料を差し替えた場合は、問題、ヒント、視覚実験、模範的な説明、判定基準の整合性を再確認します。自由なPDFをその場で追加して教える機能は標準の教材モードに含めず、必要な場合は別の自由学習モードとして扱います。

### 教材の前処理

元教材をそのまま渡してAIに教え方を任せず、教材作成時に次の順で構造化します。目的は本文の要約ではなく、「前提として渡す情報」と「学習者自身に考えさせる内容」を分けることです。

```text
固定された元教材
        ↓
必要な前提を抽出する
        ↓
前提から推察できる内容を理解課題へ分ける
        ↓
前提が多すぎる場合は教材を分割する
        ↓
学習段階・整理問題・判定基準を定義する
        ↓
段階ごとの共通PolicyとローカルPolicyを割り当てる
```

定義、固有名詞、数字、公式、記号、教材内で固定する前提は、後の理解に必要な最小限に絞ります。推察できる説明は前提の提示から極力省き、理解段階の問いと判定基準に残します。元教材の意味や成立条件を変えず、各前提・課題がどの資料に基づくかを確認できるようにします。

固定資料と学習対象の前提は`input.md`またはそこから参照する`input/`の教材定義に置きます。進行規則は`instructions.md`や`work/guideline.md`、評価基準は`work/rubric.md`などに置き、同じ定義を重複させません。AIによる前処理の結果も、教材作成者が確認してから指導に使用します。

### 既習知識の単位

応用で過去の学習を参照する場合は、レッスン全体だけでなく、一問で確認できる程度の概念・関係を1単位とします。必要に応じて、単位の識別子、出典となる教材と版、前提・関係・結論の区分、関連する単位を教材側に定義します。

「覚えた」「理解した」「応用した」という到達状態と、その判定根拠は学習者ごとの記録に残します。教材の定義と学習者の状態を混同せず、未確認の知識を学習済みとは扱いません。記録の保存先と必須項目は各教材の`Output.md`で定義します。

## Skill

Skillは、Inputを理解と学習記録へ変換する処理能力です。この文書でいうSkillは概念上の区分であり、必ずしも`SKILL.md`という名前のファイルを必要としません。

Learning Toolsでは、主に次の処理をSkillとして扱います。

- 問題の意図と学習目標を読み取る
- 問題に応じた質問を生成する
- 回答から誤解や不足している考え方を推定する
- ヒントを段階化する
- 同じ内容を別の言葉、式、図で説明する
- 条件を変えた問題を生成する
- Pythonで計算や検証を行う
- MatplotlibでFigureまたはアニメーションを生成する
- 視覚実験の結果と原理を結び付ける
- 最終説明を判定基準と照合する
- 承認された既習教材と学習記録を検索し、知識の接続を支援する
- 回答の誤りの種類を診断し、戻る学習段階を選ぶ
- 学習過程をレポートへ整理する

### 視覚実験

視覚実験は、知る担当が興味や予想を引き出す場合や、理解担当が関係を確かめさせる場合などに使用します。教材設計、学習段階、教師ロール、Skillを決めた上で、必要な実装手段を選びます。

プログラムは答えを先に表示する装置ではなく、学習者の予想を検証し、理解を補助する実験装置です。

```text
教材固有のパラメーター
        ↓
計算・判定ロジック
        ↓
Matplotlib Figureまたはアニメーション
        ↓
Streamlitによる表示
```

教材固有の計算・判定ロジックと、Streamlitによる画面制御を分離します。このリポジトリはプログラミングを教えることを主目的としないため、学習者へソースコードを見せることは必須ではありません。

教材ロジックは、可能な範囲で次のような呼び出し方へ揃えます。

```python
def create_figure(parameters):
    return fig

def create_simulation(parameters):
    return fig, animation
```

Streamlit側は、パラメーターの受け渡し、実行操作、Figureの表示に専念し、教材固有の計算式や判定ロジックを重複して持ちません。画面は問題文全体を動かすのではなく、必要なFigureまたは実験領域を更新する構成を優先します。

Streamlitが適さない教材では、無理に使用する必要はありません。視覚情報、音声、動画、対話だけの教材も同じ自動化モデルで扱えます。

### Python実行環境

Python教材では、環境を再現できるように必要なライブラリを`requirements.txt`へ記載します。

- 教材フォルダに`.venv`がある場合は再利用する
- `.venv`がない場合は必要に応じて作成する
- プログラムは原則として`.venv`内のPythonで実行する
- PC全体のPython環境へ直接ライブラリを追加しない
- `.venv`はGitへ追加しない
- 実行環境そのものではなく、再現に必要な定義だけを公開する

## Policy

Policyは、Skillを使用する順序、条件、制約、停止基準を定義します。AIが一般的な質問回答へ戻らず、選択された問題の指導に特化するための中心的な要素です。

### 教材作成者が決めること

教材作成者は、教員、塾講師、研修担当者、業務の専門家などを想定します。次を教材ごとに定義します。

- 学習対象となる固定資料
- 学習目標
- 覚える前提と、自力で導かせる内容の区別
- 学習段階ごとの教師ロール、扱う範囲、到達条件
- 必ず最初に出す問題
- 問題を出す順序と進行条件
- よくある誤解や誤答
- 誤解ごとの質問と段階的なヒント
- 使用する視覚情報や実験条件
- 正解を示してよい条件
- 理解度の判定基準
- 理解できなかった場合の復習先
- あらかじめ用意する整理問題と、誤りの種類ごとの戻り先
- 応用で参照してよい既習教材と、説明段階の評価基準

AIは教材作成を補助できますが、学習範囲、模範的な説明、判定基準は教材作成者が確認したものを正本とします。

### 共通PolicyとローカルPolicy

この文書を共通Policyとし、教科・単元ごとの具体的な教え方をローカルPolicyで定義します。教科の方針がある場合は教科の文書を参照し、単元の方針は各教材の`instructions.md`や`work/guideline.md`に置きます。

例えば、知る担当の目的は共通して「興味を持たせる」ことですが、生物では写真や分類、地学では地図や時間変化、物理では予想や実験、文章教材では身近な事例や問いを使えます。一つの巨大なプロンプトにまとめず、共通の目的と教材固有の手段を分けます。ローカルPolicyは固定教材の範囲や判定根拠を守る共通方針を維持し、段階ごとの具体的な条件を定めます。

### 学習段階と教師ロール

次の6段階を基本形とします。教師ロールは対話上の役割であり、別々のAIやプログラムを用意することは必須ではありません。

| 段階・担当 | 目的 | 主なPolicyと確認内容 |
|---|---|---|
| 知る | 興味を持たせ、思考の入口を作る | 既有知識と予想を引き出し、問いを広げる。正解を急がず、教材作成者が指定した導入から始める |
| 覚える（前提整備） | 後の理解に必要な前提を定着させる | 少数の前提だけを提示し、正確に再生できるか確認する。本文全体や推察可能な結論を先に説明しない |
| 理解する | 前提から意味・関係・理由を自力で導く | 答えを先に示さず、「なぜ」「どういう意味か」「何が違うか」を問い、関係を言語化させる。必要なら図や実験を使う |
| 応用する | 複数の既習内容から必要な知識を選び、組み合わせて使う | 許可された過去教材と到達記録を参照し、学習者自身に必要な知識を選ばせ、今回の問いとの接続を説明させる |
| 整理する | 複数の理解内容を構造化できているか確認する | 教材側に用意された整理問題を出し、必要な要素、前提、因果関係、抜け、丸写しでないこと、全体の構造をレビューする |
| 人に説明する（口頭試問） | 前提知識のない第三者へ伝えられるか確認する | 原則として途中でヒントや訂正を挟まず、説明終了後に伝わりやすさと教材整合性をまとめて評価する。文字での説明にも適用できる |

理解は「前提から、より多くのことを自力で導き出せること」とします。前提の再生だけで理解済みとは判定せず、公式を使えることと、その関係や成り立ちを説明できることも区別します。

覚える段階で理由を問われた場合は、「今はこの教材の前提として使い、理由は理解段階で扱う」と明示し、後で扱う問いとして残します。理解段階では教材で置いた前提から何が導けるかを考えさせ、その前提の由来や成立条件は教材が定めた範囲で扱います。教材内の前提と一般的な事実を区別し、前提の正しさを争う議論へ無制限に広げません。

応用は自由連想や教材外の知識追加にせず、学習済み教材、到達済みと記録された知識、同一テーマの別レッスン、教材作成者が許可した比較対象を優先します。履歴を参照できない場合は既習と推測せず、教材で指定した知識を確認してから進めます。

説明担当は、整理担当を通過した学習者の説明を最後まで聞き、原則として前段階へ戻しません。独自解釈が混ざった場合も終了後に教材の前提との違いを伝えます。説明の失敗だけで理解不足と断定せず、説明の品質と教材整合性を別に記録します。基準を満たさない場合は未達の点と復習案を残し、合格扱いにはしません。

### AIの共通指導規則

- 固定資料と教材ガイドラインの範囲で指導する
- 必ず指定された最初の問題から開始する
- 原則として一度に一つの問題を扱う
- 現在の学習段階に対応する教師ロールのPolicyを使う
- 回答内容から誤解を推定し、担当に応じた質問、視覚実験、戻り先を選ぶ
- プログラムの実行結果だけで理解済みと判定しない
- 学習者が理由を説明するまでは学習完了にしない
- 教材ごとの判定基準を満たした場合だけ、理解できたと判定する
- 判断根拠が不足する場合は再質問し、推測だけで合格にしない
- 教材範囲から外れる質問には、現在の問題の理解に必要な範囲で答える

### 自力で考えさせる課題と視覚実験の規則

従来の「予想 → 実験 → 理由の説明」という指導は、知る・理解する・応用する段階の該当課題で維持します。

- 問題を提示したら、最初に学習者へ予想または考えと、その理由を質問する
- 学習者が回答する前に正解や完成した式を示さない
- 不正解の場合も、最初は答えではなく考え方のヒントを示す
- 予想を検証する視覚実験は、学習者が予想を回答した後に行う
- 一度の実験では、原則として一つの条件だけを変更する
- 実験後は結果の理由を学習者へ質問する

知る段階の導入として現象や写真を先に見せる場合は、検証実験と区別し、結論を先に明かさない構成を教材側で指定します。覚える担当による前提の提示、整理担当による診断、説明担当による回答終了後のレビューには、それぞれの段階のPolicyを適用します。

### 問題の進行

最初の問題は教材作成者が固定します。AIは、この問題を省略したり別の問題に置き換えたりしません。

教材作成者は、固定された最初の問題を入口として、段階ごとの課題と進行条件を定義します。既存教材を6段階に対応させる際も、最初の問題、学習目標、実験の意図、判定基準を維持します。各段階を別のレッスンや画面へ分割する必要はありませんが、到達確認を省略して自動的に通過扱いにはしません。

```text
知る → 覚える → 理解する → 応用する → 整理する → 人に説明する
                                          │
                                          ├─ 前提の誤り → 覚えるへ
                                          ├─ 因果関係の誤り → 理解するへ
                                          ├─ 既習内容との接続不足 → 応用するへ
                                          └─ 全体の構造化不足 → 整理を続ける
```

整理担当は誤答を直接直して終わらせず、回答の根拠から戻り先を診断します。原因を判断できない場合は再質問し、戻った担当で必要な確認を終えたら、整理問題で改めて確認します。整理問題はその場で自由生成せず、用意された問題と評価基準を使います。

実装する場合は、現在の段階、対象の知識単位、判定根拠、次の段階または戻り先を持つ状態遷移として扱えます。次の従来の回答別分岐は、段階内で質問や支援を選ぶ基本として引き続き使います。検証・応用への進行は教材が定めた到達条件に従います。

```text
固定された最初の問題
        ↓
学習者の回答
  ├─ 十分に理解している → 検証または応用問題
  ├─ 一部理解している   → 追加質問または視覚実験
  └─ 誤解がある         → 段階的なヒントまたは補助問題
```

学習の最後には、原理や判断理由を学習者自身の言葉で説明する問題を置きます。

### 理解度判定

理解度は、正解したかどうかだけで判定しません。教材ごとの基準に基づき、少なくとも次の観点を確認します。

- 結論を答えられる
- 結論に至る理由を説明できる
- 視覚実験を使用する場合は、実験と原理の対応を説明できる
- 条件を変えた問題へ考え方を適用できる
- 成立条件や例外を区別できる

判定は「十分理解」「一部理解」「要復習」など、次の学習行動につながる表現を使用します。単語の有無だけで機械的に判定せず、回答の因果関係を確認します。

前提の再生、前提からの推論、既習知識の選択と接続、全体の構造化、第三者への伝達を区別して評価します。整理段階では内容の正しさと構造、説明段階では伝達可能性と教材整合性を確認し、一つの総合点だけで到達状態を置き換えません。

企業研修や安全教育などでは、AIの判定だけを正式な認定とせず、承認済みの資料と判定基準、教材の版、回答履歴を確認できるようにします。必要に応じて担当者が最終確認します。

## Output

Outputは、利用者が受け取る成果物と、その保存先、必須性、完成条件を定義します。各教材の具体的な定義は、その教材の`Output.md`を唯一の正本とします。

Learning ToolsのOutputは模範解答だけではなく、実行した学習過程をまとめた記録です。標準的な学習レポートには次を含めます。

- 使用した固定教材とその版
- 取り組んだ問題
- 学習者の最初の予想と回答
- AIから出した質問とヒント
- 実行した視覚実験とパラメーター
- 観察した結果
- 学習者による最終説明
- 理解できた点
- 曖昧な点または誤解していた点
- AIによる理解度の講評と根拠
- 到達を確認した知識単位と学習段階、その根拠
- 段階を戻した場合の誤りの種類、戻り先、再確認の結果
- 応用で参照した既習教材や知識（使用した場合）
- 説明の品質と教材整合性の評価、後で扱う問いが残っていればその内容
- 次に取り組む問題や復習計画

教材によっては、解説、練習問題、解答、Figure、音声、動画、画面表示などもOutputになります。

学習レポートは、学習者を単に採点するものではありません。今回の学習過程を振り返り、次の学習へつなげるための学習ノートまたは研修記録として扱います。

実験を行わない教材では実験パラメーターなどを要求せず、実際の対話・課題に対応する項目を使います。段階別の記録を既存教材へ導入する際は、その教材の`Output.md`へ必要な項目を反映してから運用します。

## 教材フォルダの標準例

```text
topic-name/
├─ README.md
├─ input.md
├─ processing.md
├─ instructions.md
├─ Output.md
├─ requirements.txt          必要な場合
├─ app.py                    Streamlitを使用する場合
├─ topic_logic.py            計算・Figure生成が必要な場合
├─ input/
│  └─ problem.pdf            例。文章教材や構造化した教材定義でもよい
├─ work/
│  ├─ guideline.md
│  ├─ misconceptions.md      必要な場合
│  └─ rubric.md              必要な場合
└─ output/
   └─ learning-report.md     実行時に生成
```

小規模教材では、誤解、ヒント、判定基準を`work/guideline.md`へまとめても構いません。内容を分割する場合も、同じ定義を複数のファイルへ重複させません。

テストで生成したFigure、PDF、学習レポート、中間ファイルの公開前整理は、リポジトリ直下の`Localrule.md`に従います。
